# Release Guide

This guide describes the release path for V-Paste maintainers.

## Release Types

V-Paste can publish two kinds of releases:

- Source release: tag the repository and attach source archives generated by GitHub.
- Binary release: attach a signed and notarized macOS ZIP or DMG.

Start with source releases if Developer ID signing and notarization are not ready yet.

## Versioning

The first open-source release is `1.0.0` with build `1`. The current release line is `1.0.1`.

Before each release, update the app target build settings in `V-Paste.xcodeproj`:

- `MARKETING_VERSION`
- `CURRENT_PROJECT_VERSION`

Then update `CHANGELOG.md` with the release date and notable changes.

## Verification Checklist

Run tests:

```bash
xcodebuild test \
  -project V-Paste.xcodeproj \
  -scheme V-Paste \
  -configuration Debug \
  -destination 'platform=macOS' \
  -derivedDataPath build/DerivedData
```

Build and package local artifacts:

```bash
./script/package_release.sh
```

Check the generated app bundle:

```bash
codesign --verify --deep --strict --verbose=2 build/release-staging/V-Paste.app
spctl -a -vv build/release-staging/V-Paste.app
```

`spctl` will reject unsigned or ad-hoc signed builds. That is expected for local unsigned artifacts and not acceptable for public binary distribution.

## Signed Binary Release

For public binary releases, use a Developer ID Application certificate and notarization.

Example:

```bash
export CODESIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)'
export NOTARY_PROFILE='vpaste-notary-profile'
./script/package_release.sh
```

The script signs the staged app when `CODESIGN_IDENTITY` is set. When both `CODESIGN_IDENTITY` and `NOTARY_PROFILE` are set, it submits the DMG for notarization and staples the ticket.

Create the notary profile once with:

```bash
xcrun notarytool store-credentials vpaste-notary-profile \
  --apple-id you@example.com \
  --team-id TEAMID \
  --password app-specific-password
```

## GitHub Release Checklist

1. Confirm the working tree is clean.
2. Run the full test command.
3. Update `CHANGELOG.md`.
4. Commit release prep.
5. Create and push a version tag.
6. Create a GitHub Release from the tag.
7. Attach notarized binary artifacts only if Gatekeeper validation passes.

```bash
git tag v1.0.1
git push origin v1.0.1
```
